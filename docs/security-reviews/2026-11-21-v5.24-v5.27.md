## L1 — LOW — Save as text keeps replies the reply filter has hidden (ACCEPTED)

- Where: `composeThread` keeps every `article.post-card` not inside
  `[hidden]` (public/js/thread-text.js:103). The reply filter hides
  non-matching replies with `data-filtered-out` and
  `.replies-list > [data-filtered-out] { display: none; }`
  (public/js/reply-filter.js:35, public/styles.css:3672), not with
  `hidden`. So a thread saved while a filter is typed still contains the
  filtered-out replies. The module comment (public/js/thread-text.js:23)
  says filtered replies are skipped.
- Impact: none across a trust boundary. Every such reply was already sent
  to this reader by the server (block pairs, bans and staff-hidden posts are
  filtered server-side by the visibility law before the page gets them) and
  shows again the moment the filter box is cleared. Spoilers in those
  replies stay masked, folded bodies stay out.
- Accepted: the filter is a reading aid, not an access control. Making the
  export honour it is a behaviour change, outside a security-fix lane.

## I1 — INFO — a hash change can target a filtered-out reply

- Where: `isShown` checks `closest("[hidden]")` only
  (public/js/reply-anchor.js:79). With a reply filter typed, a
  `#reply-<id>` hash change for a filtered-out reply scrolls to and outlines
  a `display: none` card, which does nothing visible. No content is shown
  or fetched. No fix.

## I2 — INFO — high contrast makes a revealed spoiler ink on ink

- Where: `.spoiler-revealed` paints `background: var(--paper-shadow)` with
  the inherited ink colour (public/styles.css:3281). High contrast sets
  `--paper-shadow` to the same value as `--ink` (#000000 light, #ffffff
  dark; public/styles.css:3351, 3382, 3414), so a spoiler the reader has
  revealed is unreadable. An unrevealed spoiler is still
  `color: transparent` on ink (public/styles.css:3272), so nothing is given
  away — this is a reading defect, not a disclosure. Left for a normal
  feature/fix lane; the pin below only holds the masking side.

## Checks that passed

- **Pronouns at read (v5.24.0 S1).** `applyWordFilter(readPronouns(...))`
  on the visible-profile branch only (api/profiles.mjs:141); the block-pair
  refusal never carries pronouns. Pinned in wave 5.24.
- **Reply anchors (v5.25.0).** `REPLY_HASH_PATTERN` is
  `^#reply-([0-9]{1,15})$` (public/js/reply-anchor.js:31); the hash is
  never put in a selector — cards are found with the fixed
  `article.post-card` selector and an `id` comparison
  (public/js/reply-anchor.js:90). `card.id` is only set from a plain-digit
  post id (public/js/reply-anchor.js:61-63). The copy link is built from
  `postPermalink` + the digit anchor; a non-digit id copies nothing. One
  `hashchange` listener per window (WeakSet). Nothing fetched or stored.
  Pinned: selector-shaped, unicode-digit, padded and over-long hashes are
  refused; only the fixed selector is ever queried; a non-digit post id
  gets no anchor.
- **Save as text (v5.26.0).** Built only from the cards already in `main`
  (the thread page is the only caller of `createPostCard` that puts cards
  there); author, time and body blocks only — no edit-history panel, no
  open edit form, no hidden blocks, unrevealed spoilers masked as
  `SPOILER_MASK`, folded replies keep only their header. Plain text Blob
  (`text/plain;charset=utf-8`), no request. The object URL is revoked in a
  `finally` (public/js/thread-text.js:152-157), also when the click throws.
  Filename: NFKD, combining marks dropped, then only `[a-z0-9-]`, max 60,
  `thread` fallback; the id is appended only when it is 1-15 digits
  (public/js/thread-text.js:128-132), so RTL overrides, control characters,
  path separators and reserved characters cannot reach the name. Pinned.
- **Reading progress (v5.26.0).** One bar and two passive listeners; a new
  start stops the old one first; `renderRoute` stops it on every route
  change (public/js/app.js:225), and the post route has no `await` after its
  render-version check, so a stale render cannot start a bar on another
  page. The width is set through `style.width` (CSSOM), which
  `style-src 'self'` allows. Pinned: ten renders leave one scroll, one
  resize and one hashchange listener and one bar; stop removes both scroll
  listeners and the bar.
- **Storage keys (v5.25.0, v5.27.0).** `forum-quiet-hours` is account-side
  and wiped on sign-out (`clearAllQuietHours` in `wipeAccountLocalData`,
  public/js/routes/account-nav.js:275). `forum-line-spacing`,
  `forum-link-underline` and `forum-contrast` are device preferences that
  survive sign-out; each only ever stores one of its fixed values. Quiet
  hours stores exactly `{enabled, start, end}`. The storage sweep lists the
  two new device-preference modules. Pinned: junk select values store the
  default; extra fields never reach the quiet-hours value.
- **theme-preload.js (v5.27.0).** Classic script, loaded by
  `<script src>` before the stylesheet applies; the new code sits in a
  block, so it adds no global. Values read from storage are compared
  against fixed strings before they reach `dataset` or `classList`. One
  `prefers-contrast` change listener for the life of the document (by
  design, not a leak). No eval, no markup sink. index.html gained only
  `modulepreload` links — no inline script — and the CSP
  (`script-src 'self' https://challenges.cloudflare.com; style-src 'self'`,
  api/vendor/http.mjs) is unchanged. Pinned.
- **High contrast and print CSS (v5.26.0, v5.27.0).** High contrast only
  re-weights colour tokens and adds outlines; no rule hides anything or
  touches spoilers, the footer or the source link. Print adds
  `.reading-progress` to the hidden list; the footer paragraph stays
  `visibility: hidden` with `[data-source-link]` visible, so the AGPL §13
  link still prints (pinned in wave 5.24). Pinned: high-contrast rules
  never touch `.spoiler`, `.site-footer` or the source link and never hide.
- **DOM writes.** Every new module writes text with `textContent` or
  `createTextNode` and attributes with `setAttribute`/`dataset`; no
  `innerHTML` (pinned per module by the wave 5.25-5.27 tests).
- **gitleaks allowlist (1f9bcd9).** One more exact, anchored value
  (`^PENDINGSECRETPENDINGSECRET234567$`), `regexTarget = "secret"`,
  `useDefault = true`, no `paths`/`stopwords`/`commits` allowlist. Pinned:
  every allowlist entry is an anchored literal of letters, digits and `-`.
