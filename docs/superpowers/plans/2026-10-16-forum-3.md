## Milestones

### Milestone A — media (dedup + marketplace)
- [ ] A1 dedup serving: content-addressed resolve by hash in the serve path (attachments approved w/o chunks → canonical; approved gif) + tests
- [ ] A2 marketplace: POST /api/gifs (upload ≤10 MiB GIF; dedup: approved hash returns the existing gif; pending otherwise), GET /api/gifs (approved list + use_count), GET /api/gifs/:id (serve; hybrid visibility), gif admin queue (GET /api/admin/gifs + approve/reject reusing the attachments queue idiom)
- [ ] A3 composer: GIF button → dialog picker (approved gifs, lazy <img> grid, multi-select up to 3 → attaches via gifIds fields on posts/replies = approved attachments referencing the hash; use_count++ per use); tests

### Milestone B — profiles
- [ ] B1 custom CSS: POST /api/me/css (≤20 KiB; scoping + property blocklist at SERVE time, raw text stored), css_status mirror of avatars (pending keeps serving the approved one); admin queue (GET /api/admin/css + approve/reject); profile serving of approved CSS via a <style> (CSP style-src needs 'unsafe-inline' — the scoping + approval + url() same-origin CSP is the compensating control; document the residual risk); tests (scoping/unit: selector prefixing, blocklist, keyframes passthrough)
- [ ] B2 banner: whitelisted banner color KEY + short filtered banner text; render + editor swatches; tests
- [ ] B3 flairs: flair (≤32 chars, filtered) under the name; self-set; tests
- [ ] B4 badges: auto-awarded (posts/replies milestones: 1/10/50/100/500; "suggestion accepted" = approved suggestion thread author? simple counters) shown next to flair; badge defs table? compute at read — tests
- [ ] B5 report-a-profile: POST /api/users/:id/reports (bio/flair/css reason category); queue shows profile reports; tests

### Milestone C — interactions
- [ ] C1 subscriptions: thread_subscriptions table (user, root, UNIQUE); bell-ish button on threads; replies fan out to subscribers (dedup vs mentions/author-notify); notifications carry thread context; unsubscribe; tests
- [ ] C2 @mentions: parse "@username" in post/reply create (mention rows or direct name resolution), notification fan-out to the mentioned member (dedup vs reply-notify), autocomplete in composers (GET /api/users/search exists — reuse SEARCH_USERS_SQL), render @name highlighted; tests
- [ ] C3 polls: migration (poll table + poll_votes FK'd), POST creates a poll on a root (composer toggle? simple separate flow: poll button in composer → dialog: question + up to 4 options), vote endpoint (member, one per poll; changeable until close?), results bars rendered for all; tests

- [ ] C5 pinning: posts.pinned_at; admin pin/unpin buttons on cards; pinned roots float first in home feed (stable pinning order); tests

### Milestone D — platform
- [ ] D1 search upgrades: param search replies' text (mode=deep) + author filter (by=session or username); tests
- [ ] D2 leaderboard: /api/leaderboard (7-day aggregate: threads+replies+reactions received; top 10) + /leaderboard page (trophy row); tests

- [ ] D4 version 3.0.0 + claude.md docs + final whole-branch review + owner push/deploy steps

## Global constraints
- CSP: style-src gains 'unsafe-inline' ONLY for the scoped custom-CSS feature (documented compensating controls); img-src stays 'self' data:.
- All user text through the word filter; sizes capped server-side; rate limits mirror sibling endpoints.
- Everything display-only stays out of sorting except pinning (explicit) and suggestions (existing).
- Tests per feature; battery green before each commit; version bump only at D4.

## Review focus
- Custom CSS sandbox (B1) and the marketplace moderation loop (A2/A3) are the two security-critical surfaces of 3.0 — each gets its own review.
- Polls (C3) and subscriptions (C1) write new notification paths — verify no notification spam loops.
