# Forum v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the 13 approved v2 features (moderated avatars, mod role, reaction toggling, Turnstile on replies, one-level threading, reply bumps, word filter, 10k bio, socials + Polytoria, notifications, ban screen).

**Architecture:** Single migration 0002 (users rebuild via `PRAGMA defer_foreign_keys`), split `worker.mjs` into `api/*` modules so tasks touch disjoint files, then feature tasks sequenced by file ownership, then all frontend in one later pass.

**Tech Stack:** Cloudflare Workers, D1, Wrangler rate-limit bindings, node:test (Node ≥ 22; runtime is v26). No new npm dependencies.

**Spec:** `docs/superpowers/specs/2026-10-15-forum-v2-design.md` (implementers must read it; this plan is the executable form).

## Global Constraints

- **No git operations. The user commits.** No task may run `git add/commit/push`; a finished task just leaves the tree clean and tests green. ("Commit" steps from the standard template are replaced by "verify tree matches expectation".)
- Every task: full `npm test` green + `npx wrangler deploy --dry-run` clean before hand-back.
- All SQL parameterized; no string interpolation of user input into SQL.
- Frontend rendering stays `textContent`-only — no `innerHTML`, no `insertAdjacentHTML`.
- Remote D1 (`db:migrate:remote`) is EXPLICITLY FORBIDDEN in tasks; remote migration is run by the user per CLAUDE.md.
- Tests use the existing mock patterns (`mockD1Batch`, `envWithLimiter`) from `tests/worker.test.mjs`.
- Password/security code unchanged: PBKDF2 iterations, pepper, session hashing stay as-is.

## Review Focus

(the failure modes the spec implies but tests may miss — each pinned by a named test in its owning task)

1. Empty filter list must mutate NO text — `test("an empty filter list is a no-op")` (Task 3).
2. Filter replacement is length-preserving so the 2000-char check cannot be bypassed — same task.
3. Composite feed cursor accepts only `<seconds>_<id>` format; rejects garbage without error-500 — `test("feed cursor validation")` (Task 6).
4. Guest requesting an unapproved pending-only user's avatar gets 404, the owner gets 200 — `test("pending avatar visibility")` (Task 8).
5. Notification cap: replying 51+ times keeps exactly the newest 50 rows — `test("notification cap prunes to the newest 50")` (Task 4).
6. Demote/promote refuses to touch admins (including self) — `test("promote/demote refuse admin targets")` (Task 8).
